# 参加者セットアップ（GitHub Codespaces・ワンクリック）

ワークショップは **ブラウザだけ**で動きます。インストールは不要。必要なのは **GitHub アカウント**と**ブラウザ**だけです。
（教材本体は [workshop.md](workshop.md)。このページは「動かす環境を用意する」ところまで。）

---

## 1. Codespace を起動する（30秒）

1. このリポジトリのページを開く
2. 緑の **`Code`** ボタン → **`Codespaces`** タブ → **`Create codespace on main`**
3. **マシンは 2-core か 4-core を選ぶ**（下の「マシンサイズ」参照）
4. しばらく待つ（初回はコンテナのビルドで 1〜3 分）。VS Code がブラウザで開けば準備完了

`.devcontainer/` に **Go 1.26 + `GOEXPERIMENT=simd`** が入っているので、開いたらそのまま使えます。

## 2. 動作確認（これが通れば準備OK）

VS Code 下部のターミナルで:

```sh
make test     # 正しさ確認。PASS が出ればOK
make bench0    # ベースライン(スカラ全探索)を1回測る
```

数字が出たら [workshop.md](workshop.md) の「03. まず動かす」へ進んでください。

---

## マシンサイズ（2-core / 4-core 推奨）

| 選択 | いつ使う |
|---|---|
| **2-core** | 無料枠を一番節約したい。本ワークショップはこれで十分 |
| **4-core** | ベンチを少し安定させたい（推奨） |
| 8-core 以上 | 不要。無料枠を早く消費するだけ |

> ⚠️ 学習目的では**絶対値は重要でなく**、各自が「自分の点を打つ」設計です。大きいマシンを選んでも結論は変わらないので、小さめで大丈夫。

## 費用：かかりません

- 計算リソースは **起動した自分の GitHub アカウント**の無料枠（**月 120 コア時間**）から引かれます。
- 40分のワークショップは 4-core でも **3 コア時間弱**＝無料枠の数%。**実質 ¥0** です。
- 終わったら Codespace は止めてOK（30分操作が無ければ自動停止。`Code → Codespaces` から手動停止/削除も可）。

## どの CPU が当たっても本編は動きます

Codespaces は当たる CPU（Intel/AMD・世代）を選べませんが、**本編が使う SIMD は AVX2 + FMA だけ**（過去10年の x86 がほぼ全部対応）なので、**どの CPU でも全ステージ再現します**。
ただし**出る数字は CPU で変わります**（それが教材の狙い＝各自のベンチで点を打つ）。AVX-512 は本編では使いません。

## 困ったとき（フォールバック）

| 状況 | 対処 |
|---|---|
| **会社/組織アカウントで Codespaces が無効**（組織ポリシー） | 個人の GitHub アカウントで参加するか、講師に共有環境を相談。または下の「ローカル devcontainer」 |
| Codespaces をどうしても使えない | **ローカル devcontainer**: VS Code + Docker Desktop で「Reopen in Container」。※SIMD の数字を出すには **amd64 マシン**が必要（Apple Silicon は次項） |
| 手元が **Apple Silicon (Mac)** | `make test`（正しさ）は arm64 のスカラ版で通りますが、**SIMD の数字は出ません**。数字を取るなら Codespaces を使ってください |
| 起動が遅い / 失敗する | 一度 Codespace を削除して作り直す。それでもダメなら講師へ |

困ったら早めに講師に声をかけてください。当日は会場ネットワーク障害時に講師画面でのライブ進行に切り替えます。
